\section{Reproducibility}
\label{app:repro}

\subsection{Commands}
All commands run from the repository root. Translation and voice generation for local models used a GTX~1070 (8\,GB) in float32; the 3.3B model was queried through the deployed API. The MMS ASR run ran out of GPU memory on a long utterance after 566 of 827 files and was resumed on CPU (same weights, float32, greedy decoding). The 1.3B model's beam search exceeded the card's memory and spilled into shared memory, which only slowed it down.

\begin{small}
\begin{verbatim}
python eval/fetch_data.py --fleurs
python eval/mt_translate.py --system nllb-600m \
       --direction both --device cuda
python eval/mt_translate.py --system nllb-1.3b \
       --direction both --device cuda
python eval/mt_translate.py --system nllb-3.3b \
       --direction both
python eval/mt_score.py
python eval/asr_eval.py --system farmerline --device cuda
python eval/asr_eval.py --system mms --device cuda
python eval/asr_eval.py --score
python eval/tts_eval.py --generate mms
python eval/tts_eval.py --generate omnivoice
python eval/tts_eval.py --score
python paper/make_numbers.py
\end{verbatim}
\end{small}

Fine-tuning (\S\ref{sec:finetune}) ran on a free Kaggle T4 through \texttt{training/finetune\_kaggle.ipynb}, which executes:

\begin{small}
\begin{verbatim}
python training/build_parallel.py
python training/filter_opus.py
python training/finetune_nllb.py \
       --model facebook/nllb-200-distilled-1.3B \
       --out nllb-kam-ft
\end{verbatim}
\end{small}

\texttt{finetune\_nllb.py} writes \texttt{eval\_report.json} (base and fine-tuned scores) next to the model; it is published with the model and copied to \texttt{eval/results/finetune\_nllb\_1.3B.json}. Training data are pinned to commit \texttt{9617445} of the community corpus; the held-out stories are chosen with seed 1234.

\subsection{Checklist}
\begin{itemize}\itemsep0pt
  \item Test sets public, fixed, hashed: yes.
  \item Same decoding as deployed system: yes (shared code in \texttt{app/translate.py}).
  \item Confidence intervals and paired tests: yes, 2,000 resamples, seed 1234.
  \item Normalisation tiers reported side by side: yes.
  \item Fallback contamination of 3.3B outputs prevented: yes, run aborts on any non-3.3B answer.
  \item Human evaluation: no.
\end{itemize}

\section{Deployment Notes}
\label{app:deploy}

Issues we met putting the system on free Hugging Face hardware, recorded because they are not obvious from the documentation:
\begin{itemize}\itemsep0pt
  \item The free CPU tier and Docker Spaces required payment for our account; ZeroGPU is available to Gradio-SDK Spaces only, so a FastAPI app has to be mounted on a Gradio app.
  \item ZeroGPU refuses to start unless at least one \texttt{@spaces.GPU} function exists at import time, and \texttt{spaces} must be imported before \texttt{torch}.
  \item Gradio's server-side rendering intercepted our POST routes (HTTP 405); \texttt{ssr\_mode=False} fixed it.
  \item Casting OmniVoice to float16 produced silent audio; it runs in float32.
  \item \texttt{transformers} starts a background download of a safetensors copy of \texttt{.bin}-only checkpoints; \texttt{DISABLE\_SAFETENSORS\_CONVERSION=1} avoids doubling disk use.
  \item GPU time is requested per call in proportion to text length, because anonymous visitors share one quota.
\end{itemize}

\section{Negative Results}
\label{app:negative}

\begin{itemize}\itemsep0pt
  \item \textbf{Community Kamba SpeechT5.} A public SpeechT5 \citep{ao2022speecht5} checkpoint fine-tuned for Kamba contains NaN weights and produces no audio.
  \item \textbf{OmniVoice without a reference.} Without a clone prompt OmniVoice picks a voice per call, so consecutive sentences can sound like different people; we clone fixed FLEURS speakers instead.
  \item \textbf{Gikuyu voice for Kikamba.} The closely related MMS Gikuyu voice is markedly less intelligible on Kikamba text than the Swahili one (Table~\ref{tab:tts}).
  \item \textbf{Bible LoRA.} The public NLLB LoRA trained on Bible-verse pairs did not improve FLORES scores.
  \item \textbf{A fine-tuned MMS voice.} Fine-tuning the MMS Kikuyu or Swahili VITS voice on 2.2\,h of one speaker from Digital Divide Data's Kamba dataset (about 5,000--6,000 steps on a T4) gave a voice that sounded partly Kamba but mumbled and robotic: 32.6\% character error in the ASR round trip from a Kikuyu start, against 13.3\% for the untrained Swahili voice and 7.2\% for the speaker's real recordings. Clarity fell to 46.6\% in the first 500 steps and was still recovering when training stopped.
  \item \textbf{Unfiltered mining scores.} Sorting OPUS NLLB by its mining score alone does not isolate good pairs: mid-ranked pairs still include chat noise and non-Kikamba text, which is why the language, religion and dual cross-entropy filters of \S\ref{sec:finetune} were needed.
  \item \textbf{Mined bitext.} OPUS NLLB v1 en--kam (1.63M pairs) is dominated by religious text and contains non-Kikamba target sides; we did not use it.
\end{itemize}
